# 화장실 지도 (toilet-map) 설계

작성일: 2026-11-17

## 의도
급할 때 **내 위치에서 가장 가까운, 지금 쓸 수 있는 화장실**을 몇 초 안에 찾게 해 주는 모바일 우선 웹 서비스.
실제 일반 사용자가 쓰는 것을 목표로 한다(장난감·데모 아님). 수익화는 이번 범위에서 제외.

## 목표
- 서울특별시 + 경기도 공중화장실(공중/개방/간이/이동) 표시. 약 15,330건, `미개방` 제외 시 약 14,950건.
- 첫 화면에서 현재 위치를 잡고 **가까운 순 목록** + 지도 핀을 함께 보여 준다.
- 각 항목: 이름, 거리, **지금 열림 여부**, 장애인용·기저귀 교환대 표시, **[길찾기] → 카카오맵 앱/웹 연결**.
- 서버 없이 GitHub Pages 정적 호스팅(`https://y-jaehyun.github.io/toilet-map/`).

## 비목표 (이번에는 안 함)
- 수익화(광고 등), 사용자 제보·리뷰·로그인
- 지하철 역사 내 화장실(서울교통공사 데이터 — 좌표 없음, 역 좌표와 연결 필요) → 2단계
- 데이터 자동 갱신(GitHub Actions) → 2단계. 1단계는 로컬에서 수동 실행
- 전국 확대 → 이후 (파이프라인은 시도 필터만 바꾸면 되도록 만든다)

## 안티 목표 (기술적으로 돌아가도 이러면 실패)
- 첫 화면이 느림 (모바일 LTE에서 목록이 뜨기까지 수 초 이상)
- 닫혀 있을 수 있는 화장실을 확정적으로 "열림"이라고 안내 — 판단 불가하면 "시간 확인 필요"로 표시
- 위치 권한 거부 시 아무것도 못 하는 화면

## 제약
- **원천 데이터에 좌표 없음**: 행정안전부 공중화장실정보(localdata, 매일 갱신)는 2025-02부터 위경도 제공 중단. 주소(도로명 90%, 나머지 지번)만 있음 → 지오코딩 필요.
  - 다운로드: `https://file.localdata.go.kr/file/download/public_restroom_info/info` (브라우저 UA·Referer 필요, CSV cp949)
  - 이용허락범위: 제한 없음. 출처 표기는 한다.
- 서버 없음 → 모든 데이터는 빌드 시 정적 JSON으로 생성해 저장소에 커밋.
- 키
  - 브이월드 개발키(지오코딩, 로컬 빌드에서만 사용): `~/.config/toilet-map/keys.env` 의 `VWORLD_KEY`. 저장소에 커밋 금지.
  - 카카오 JS 키(지도 표시): 브라우저 노출이 정상이며 도메인 제한(`https://y-jaehyun.github.io`)으로 보호. 저장소에 포함 가능.
  - 카카오 REST 키: 사용 안 함(결과 저장 불가 정책).

## 접근 방식 (검토안)
| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 카카오맵 + 목록 우선 (채택)** | Kakao Maps JS SDK, 위에 지도/아래 가까운 순 목록 | 한국 지도 품질 최고, 카카오맵 앱 길찾기 연결 자연스러움 / 카카오 키·도메인 등록 1회 필요 |
| B. Leaflet + OSM 타일 | 키 불필요 | 한국 상세도 낮음, OSM 공식 타일은 서비스 트래픽 금지 → 결국 이전 필요 |
| C. 목록만 + 외부 길찾기 | 가장 가벼움 | 방향·분포를 못 봄 |

사용자가 A를 선택. 실사용 대상에서 지도 품질과 앱 길찾기 연결 체감이 가장 크기 때문.

지오코딩: **브이월드 지오코더만 사용** (브이월드 키 발급 완료).
- 처음엔 "브이월드 우선 + 실패분 카카오 로컬 API 보완"이었으나, 카카오는 로컬 API 결과 좌표의 저장·활용을 허용하지 않고 실시간 호출만 허용(devtalk 공식 답변) → 정적 파일 저장 구조와 맞지 않아 제외.
  같은 답변에서 "별도 확보한 주소를 공공기관 API로 변환한 좌표를 저장해 지도에 표시하는 방식은 가능"이라고 안내함.
- 브이월드(국토교통부 지오코더 API)는 공공데이터포털 표기상 이용허락범위 제한 없음.
- 실패분은 제외하고 `geocode-failed.csv` 로 남긴다(매칭률 보고). 필요하면 이후 수동 보정.

## 구성

### 1) 데이터 파이프라인 (`scripts/`, Python 3, 로컬 실행)
1. **다운로드**: 전국 CSV 받기 → `data/raw/` (커밋 안 함).
2. **필터**: 주소 첫 토큰이 `서울특별시`/`경기도` 인 행, `개방시간 == 미개방` 제외.
3. **지오코딩**
   - 도로명주소 있으면 `type=road`, 실패 또는 없으면 지번주소로 `type=parcel` 재시도.
   - 결과는 **캐시 파일**(`data/geocode-cache.json`, 키 = 정규화된 주소 문자열)에 저장하고 커밋 → 재실행 시 새 주소만 호출.
   - 실패 건은 `data/geocode-failed.csv` 로 남겨 매칭률 확인.
   - 호출 간 간격·재시도로 한도 존중.
   - [Claude 판단] **목표 매칭률 95% 이상.** 미달 시 출시 전 주소 정규화(괄호·층수·건물명 꼬리 제거, 지번 재시도)를 추가하고 재실행. 최종 매칭률은 사용자에게 보고.
4. **개방시간 정규화** → 항목별 `hours` 필드:
   - `상시`, `24시간`, `00:00~24:00` 류 → `always`
   - `HH:MM~HH:MM`/`HH:MM-HH:MM` (자정 넘김 포함) → `{open, close}`
   - `(평일)…` 처럼 요일 조건이 붙은 것 → 평일 시간 + `weekdayOnly` 표시(주말·**공휴일**엔 "시간 확인 필요")
     - [Claude 판단] 공휴일은 정적 목록(`site/data/holidays.json`, 2026~2027)으로 판정. 매년 갱신 필요 — 갱신 안 됐으면 해당 연도는 평일도 weekdayOnly를 "시간 확인 필요"로 보수 처리.
   - 그 외(`정시` + 상세 없음, `9시간`, `불규칙`, 빈 값) → `unknown`
5. **출력**: 격자 분할 정적 JSON `site/data/tiles/<cellX>_<cellY>.json` + `site/data/meta.json`(격자 크기, 데이터 기준일, 건수).
   - 항목 필드는 축약(이름, 좌표, 구분, hours, 장애인용 유무, 기저귀 교환대 유무, 비상벨, 주소, 관리기관 전화).

### 2) 프런트엔드 (`site/`, 빌드 도구 없는 바닐라 HTML/CSS/JS)
- 로드 즉시 위치 요청 → 현재 위치 셀 + 인접 8칸 타일 fetch → 거리 계산 → 가까운 순 상위 N개 목록 + 지도 핀.
- 지도를 움직이면 보이는 영역의 타일을 추가로 불러온다(이미 받은 타일은 메모리 캐시).
- 위치 권한 거부/실패 시: 서울시청 중심으로 시작 + "지도를 옮겨 찾기" 안내, 지도 중심 기준으로 목록 갱신.
- "지금 열림" 계산은 기기 현재 시각(한국 시간 기준) 사용. 상태: 열림 / 닫힘 / 시간 확인 필요.
- 기본 정렬은 거리. 닫힘은 목록 아래로 내리거나 흐리게.
- [길찾기]: `https://map.kakao.com/link/to/<이름>,<lat>,<lng>` (모바일에서 카카오맵 앱으로 연결됨).
- 출처 표기: "행정안전부 공중화장실정보 (데이터 기준일 …)" + 좌표 변환 출처.

### 3) 배포
- GitHub 저장소 `Y-JaeHyun/toilet-map`, GitHub Pages 소스 = `site/` 를 배포하는 Actions 또는 `docs/` 대체 구성(구현 시 단순한 쪽 선택).
- 저장소 생성·공개 푸시는 외부 게시이므로 실행 전 사용자 확인. (무료 계정 Pages는 공개 저장소 필요)
- [Claude 판단] 첫 푸시 전 비밀값 검사: `keys.env`·브이월드 키 문자열이 저장소 어디에도 없는지 grep으로 확인, `.gitignore`에 `data/raw/`, `*.env`.
- [Claude 판단] 로컬 개발은 `python3 -m http.server 8000`(site/) → 카카오 앱 Web 도메인에 `http://localhost:8000`도 등록 필요(사용자 작업).

## 빌더에게 맡기는 것
- 격자 크기(예: 0.05°), 목록 기본 개수·반경, 마커 클러스터링 여부, 스타일링 세부.
- 개방시간 파서의 세부 패턴 추가(실데이터 상위 패턴 기준으로 커버리지 확인).
- 테스트: 개방시간 파서·거리 계산·타일 분할은 단위 테스트.
